# Rationale for go-gitea/gitea@c6e25135705b

## GOAL

Migrate protected branch fields into one JSON column and support system users.[^1] Use dropdown lists for push and force-push users, including Actions, and resolve the Actions system username for both API create and edit.[^2], [^3] Keep the deploy-key pseudo-user visible when present in a rule, and include the synthetic Actions user when returning push and force-push names.[^4], [^5]

## NEED

The code review noted that writing the full JSON config from an earlier read could let a stale object overwrite unrelated settings when branch settings changed concurrently; previously, only affected allowlist columns were updated.[^6] Actions could not be supplied in either API push allowlist because the name resolver queried only the user table, while Actions is synthetic.[^7], [^8] When the last deploy key was deleted, its `-3` value could remain hidden in the allowlist and silently apply to future deploy keys.[^9] Branch-protection responses omitted Actions because the existing name conversion only iterated database-backed repository readers.[^10]

## ALTERNATIVE

Use an optimistic conditional update with retry or a locking strategy shared by config writers.[^11]
