# Task summary

You are an experienced Java programmer on the torvalds/linux project. Your task is to analyze a set of sentences, identify whether they express the rationale behind a target code commit, and annotate them according to a taxonomy of rationale components.

You will be provided with:
* A list of rationale components, each one describing a different aspect that explains why the code was changed the way it was.
* The diff of the target commit, which shows how one or more code files were changed.
* A list of sentences extracted from different sources (artifacts) related to the commit, namely the commit message, pull requests, issue reports, code review comments, Javadoc comments, and inline/block code comments of the changed code.

# Instructions
* Analyze the content of the sentences, identify the rationale components that they describe, and annotate them with those components.
* Annotate the sentences individually using one or more of the provided rationale components only if the sentence contains information about those components.
* If a sentence does not describe any of the rationale components, do not include that sentence in your response.
* In your response, provide only the sentence ID and the component(s); do not include any additional information.
* Provide your response in CSV format.

# Important
Each sentence ID follows the format: CommitID_SourceID_TextID_LocalSentenceID. The IDs in this format are numbers that we use to identify different artifacts and text snippets within these artifacts. If consecutive sentences share the same CommitID_SourceID_TextID, it means they are logically grouped within the artifacts' text. For labeling the sentences, consider these groups as context (as they may give more information about the sentences), but still label the sentences individually.

# Inputs

## Rationale Components
1. GOAL: Describes what changes have been made by the developer in the code change. This is a high-level or low-level description of the code change, indicating what the developer aims to achieve with the code change.

2. NEED: Describes the specific reason, motivation, or benefit of the code change. This indicates why the developer wants to make the code change.

3. ALTERNATIVES: Describes other potential solutions considered by the developers before making the final code change. This indicates the alternative solutions discussed by the developers, but not implemented for the code change.
