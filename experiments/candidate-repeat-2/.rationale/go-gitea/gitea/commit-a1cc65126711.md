# Rationale for go-gitea/gitea@a1cc65126711

## GOAL

The change aims to resolve and proxy `<source>` element `srcset` links, use correct links for picture sources, and wrap the picture element with a link correctly.[^1], [^2], [^3] The new source visitor processes each `srcset` candidate with the same link resolution and camo handling as `img` and `video`, while preserving separators and descriptors in multi-candidate lists.[^4]

## NEED

The post-processor visits `img` and `video` nodes but not `<source>`, even though the sanitizer allows `media` and `srcset` there for `<picture>` dark/light images.[^5] As a result, a relative `srcset` can resolve against the page URL and point to the HTML file view instead of the media route, preventing the dark variant from loading.[^6] With camo enabled, an unrewritten `<source>` candidate can also cause readers’ browsers to contact the external host directly and expose their address and user agent.[^7] The author encountered the issue when a README’s dark image pointed to a `src/branch/...` URL.[^8]

## ALTERNATIVE

A reviewer proposed using `strings.Fields` or `strings.FieldsSeq` and cautioned against reinventing the wheel.[^9], [^10] The parser was reworked around `strings.FieldsSeq`, treating fields as candidate URLs or descriptors and using commas at field edges to separate candidates while preserving embedded URL commas.[^11] The reviewer later said the parser was more complicated than it looked and `strings.Fields` could not handle the needed details.[^12]
