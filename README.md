# Fine-grained-Multi-Document-Extraction-and-Generation-of-Code-Change-Rationale

Abstract: Understanding the rationale behind code changes is essential for software maintenance, yet this information is not documented consistently or in one place, rather often fragmented across different artifacts(i.e. issue report, pull request etc.). Existing approaches to rationale identification are limited and they typically focus on a single artifact, often overlooking the need of cross-document information linking. Moreover,  they do not capture fine-grained components such as "Goal" (what the change is about), "Need"(why the change is needed), etc. Despite the need of these fine-grained rationale component, it is unknown what rationale information are documented or what are the sources they are to be found. We address these challenges in two steps. First, we empirically study 63 commits from five open-source projects to analyze how rationale components are expressed across diverse artifacts that include commit messages, issue reports, and pull requests, etc. Our findings show that rationale is highly fragmented, with no single artifact capturing complete intent, for example commit message  only cover two types of rationale information whereas other additional rationale components scattered in issues, pull requests, code reviews, javadocs and code comments. Next, we introduce ARGUS, a novel LLM-powered approach that retrieves, identifies, and generates fine-grained rationale across multiple artifacts. Our evaluation shows ARGUS can identify rationale information with 93% recall and 51% precision. Our manual evaluation on the rationale description shows overall score of 4.3 in Information Coverage on 5 point scale, which showed most of the ground truth rationale can be extracted by our tool. We further evaluated our tool in a user study with 12 perticipents which shows that synthesized rationale helps understanding motive of code change and saves time to understand it.
